MODÈLE CRYPTOGRAPHIQUE

Modèle Cryptographique — Papier vs Implémentation

Matrice de clés partagées (référence) · HKDF groupe + ECDH privé (Phase 1B)

Modèle papier (base) — Matrice de clés sur le fil
  • Forward secrecy par paquet · distribution explicite des clés de session
  • Overhead O(N) — limite MTU avec grands groupes
Implémenté — Groupe (broadcast)
  • Même forward secrecy par paquet, sans Key Header
  • Tous les membres partagent group_key
Implémenté — Privé (unicast) · choix ECDH
  • Évite une ligne matrice par destinataire pour l'unicast
  • Overhead constant · confidentialité vis-à-vis des autres membres
Pourquoi ECDH pour le privé ?
Le modèle matrice distribue une clé de session par membre dans chaque paquet — adapté au broadcast groupe. Pour un message 1-to-1, ECDH X25519 dérive K_pair localement : pas de matrice, pas de fuite aux autres membres du groupe, overhead identique (42 B).
Message de Groupe
  • base_key = group_key (partagée)
  • packet_key = HKDF(group_key, src ‖ seq ‖ ts_ms)
  • overhead = 42 B
  • Relais : forward opaque — pas de dérivation
Message Privé
  • K_pair = HKDF(X25519(priv_A, pub_B))
  • packet_key = HKDF(K_pair, src ‖ seq ‖ ts_ms)
  • pub_B distribué via Hello privé (chiffré groupe)
  • overhead = 42 B (identique)
Papier (matrice) Groupe (impl.) Privé (impl.)
Distribution clé N × 32 B chiffrés / paquet group_key (.env) ECDH + Hello privé
Overhead clés O(N) — ex. 320 B / 10 membres 0 B (HKDF local) 0 B (ECDH local)
Lisible par Membres listés dans matrice Tous membres A et B seulement
Overhead total 26 + N×32 + payload + 16 42 B 42 B

CDS — MPR (JACQUET 2004)

Variante MPR — sélection Qayyum + MPR-CDS

Sélectionnable via CDSAlgorithm.MPR · liste MPR annoncée en clair dans le Hello

§1 — Sélection MPR · _select_mpr (Qayyum, RFC 3626)
  • Étape 1 : tout w ∈ N2 couvert par un SEUL y ∈ N1 force y dans le MPR
  • Étape 2 : ajouter le y couvrant le plus de N2 non couvert (tie-break id min)
  • But : le plus petit sous-ensemble de N1 qui couvre TOUT N2
§2 — MPR-CDS · _is_mpr_cds_member (Jacquet 2004, §2.4.2)
  • am_i_cds(..., CDSAlgorithm.MPR) · compute_local_mpr() pour annoncer
  • Runtime prod : élection Wu-Li par défaut — MPR annoncé mais pas sélectionné pour relais
  • Bloc MPR public Hello = AAD GCM (inaltérable)
StratégieÉlectionVue runtimeOverhead Hello
WU_LI_1999 Gateway + pruning Cas 1/2 (S_low) local_symmetric_peers voisins seuls
MPR Jacquet 2004 (a)/(b) sur MPR annoncés get_mpr() de Y* + n_mpr × anon_id
Défaut connu + comparaison Wu-Li
  • Règle 1 (Jacquet 2004) : un nœud peut entrer dans le backbone juste parce qu'il a l'id local-min, même s'il ne relaie rien (feuille id-min). Wu qualifie ces ajouts d'« inutiles ».
  • Sur petites topologies, MPR-CDS peut être PLUS GRAND que Wu-Li (ex. ligne où le min global est une extrémité). La prédiction MPR ≤ Wu-Li du préprint est asymptotique (λ→∞).
  • Correctif littérature : EMPR (Règle 1 + condition gateway « ≥2 voisins non connectés ») — hors périmètre du préprint §2.4.2, non appliqué pour rester fidèle à la formulation.
