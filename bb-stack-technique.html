TRANSPORT & SÉCURITÉ

BT Classic L2CAP + dérivation clé par paquet

Transport L2CAP
  • Symétrique : chaque nœud = server + client
  • Multi-connexions threadées (l2cap.py)
  • Auto-pairing via bluetoothctl agent NoInputNoOutput
  • Allowlist --topology · reconnexion avec backoff
Deux modes de chiffrement (keys.py)
Groupe — broadcast / chat (FF:FF:…)
  • Base : group_key (PSK .env)
  • packet_key = HKDF(group_key, info=src‖seq‖ts)
Privé — --private unicast
  • Base : clé pairwise ECDH X25519 (jamais sur le fil)
  • Pubkeys échangées via Hello private (membres seulement)
  • Même derive_packet_key(base, src, seq, ts)

Audit sécurité — état actuel

  • Révocation groupe — rotation manuelle GROUP_KEY · pas de PKT_ACK
03.5 — MODÈLE CRYPTOGRAPHIQUE

Modèle Cryptographique — Groupe & Privé

Même format paquet (42 B overhead) · deux bases de dérivation distinctes

Message de Groupe
  • base_key = group_key (partagée)
  • packet_key = HKDF(group_key, src ‖ seq ‖ ts_ms)
  • overhead = 42 B
  • Relais : forward opaque — pas de dérivation
Message Privé
  • K_pair = HKDF(X25519(priv_A, pub_B))
  • packet_key = HKDF(K_pair, src ‖ seq ‖ ts_ms)
  • pub_B distribué via Hello privé (chiffré groupe)
  • overhead = 42 B (identique)
Groupe Privé
Clé de base group_key K_pair = ECDH(A,B)
Lisible par Tous membres A et B seulement
Relais voit Ciphertext opaque Ciphertext opaque
Overhead 42 B 42 B

HELLO MESSAGES

Topologie anonyme — Deux parties

Seuls les membres connaissent la vraie identité des nœuds

Design deux parties
PUBLIC — clair, tout nœud CDS
  • anon_id = HMAC-SHA256(group_key, bd_addr)[:8]
  • seq, timestamp
  • liste des voisins par anon_id
PRIVATE — AES-GCM, membres seulement
  • vraie BD address + voisins BD
  • clé publique X25519 (32 B) — échange ECDH pour messages privés
Hello packet size ~106 B ex. 1 voisin + pubkey X25519
Intervalle 5 s hello_interval_s
Ce que chaque nœud voit
ProfilVoitPeut
Relais CDS non-membre A77F ↔ B3C2 ↔ F91A construire CDS ✅
ne voit pas qui est qui ✅
Membre du groupe anon_ids + vraies BD addresses CDS + identifier les membres ✅
Attaquant extérieur paquets chiffrés opaques rien ✅
Synthèse
La topologie reste opaque pour les non-membres. Les relais CDS font leur travail sans connaître l'identité des nœuds qu'ils servent.
CDS — CONNECTED DOMINATING SET

Rôle relais local (am_i_cds)

Runtime : HelloManager.is_relay → PacketForwarder · Référence offline : compute_cds()

Décision runtime — am_i_cds() ✅
  • RELAY si ≥ 2 peers L2CAP et ∃ paire (u, v) sans lien Hello mutuel u↔v
  • LEAF si < 2 peers, ou mesh local complet (toutes paires liées en Hello)
  • Peers L2CAP = transport.connections() uniquement (pas la table Hello)
  • Adjacence u↔v = listes 1-hop Hello mutuelles
  • Recalcul à chaque Hello / changement L2CAP · rôle visible en --chat au démarrage
Référence offline — compute_cds() (self-tests)
  • Greedy CDS sur graphe Hello fusionné (anon_ids)
  • Non utilisé pour décider le forward à l'exécution
  • Sert à valider la théorie / topologies simulées dans cds.py

Intégration PacketForwarder
  • is_relay → flood TTL vers peers ≠ ingress (octets bruts)
  • LEAF → déchiffre si dst = local ou broadcast
  • Déduplication livraison (src, seq)
  • Validé multihop sur setup linéaire 3 nœuds (nœud central = RELAY)
Synthèse
Pas de BD addresses dans la décision relais — uniquement anon_ids Hello + sockets L2CAP. En mesh radio complet (tous se voient en Hello), personne ne relaie : le flood direct suffit.
FORWARDING

Forwarding & test non-membre

Forwarding multihop (forwarder.py)
  • RELAY → forward octets bruts (sans dériver la clé)
  • LEAF / destinataire → derive_packet_key puis decrypt
  • Broadcast : base = group_key · privé (--private) : base = ECDH pairwise
  • Déduplication livraison/relai (src, seq) — pas encore fenêtre 256
  • TTL décrémenté sur le fil · AAD avec TTL=0
Exemple labo — 3 nœuds linéaires
  • Nœud A → envoie PKT_DATA broadcast
  • Nœud B (RELAY) → forward opaque
  • Nœud C → reçoit et déchiffre ✅
Test non-membre (relais hors groupe)
  • Relais avec mauvaise clé → InvalidTag à la livraison (pas au forward)
  • Forward opaque quand même en RELAY ✅
  • Membres du groupe : contenu illisible sur le relais non-membre ✅
Verdict
Un relais CDS non-membre transporte les paquets sans jamais accéder au contenu — confidentialité des relais validée expérimentalement.
