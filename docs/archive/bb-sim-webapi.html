BUBBLE-BLUE · Simulation & démo

Simulateur Web API

Interface navigateur + API REST pour comparer Wu-Li 1999 et MPR-CDS sur des topologies aléatoires, sans cartes Bluetooth. Le calcul est délégué au vrai code BB (HelloManager, PacketForwarder, cds.py) — seul le transport L2CAP est remplacé par un bus géométrique 2D.

Déroulement d'une simulation
1
Topologie — topology_gen.generate_connected_geometric place N nœuds dans un carré ; deux nœuds sont voisins si distance ≤ radius (degré moyen cible via target_degree).
2
Convergence Hello — SimEngine crée N × SimNode ; chaque step() envoie des Hellos sur le bus puis appelle refresh_cds_role() jusqu'à point fixe (ou cycle MPR détecté).
3
Rôles RELAY/LEAF — lus depuis hello_mgr.is_relay (même source que le forwarder hardware). Comparaison Wu-Li vs MPR via metrics_roles.compare_one.
4
Broadcast (option) — ForwardingSimEngine injecte un PKT_DATA via le vrai PacketForwarder.send_broadcast ; les relais forwardent ; métriques = unicast DATA et vagues de propagation.
5
JSON → navigateur — positions, arêtes, rôles, taille CDS, coût flood. Le front (sim/webapp/static/index.html) ne fait que dessiner et animer.
Endpoints REST FastAPI
RouteRôle
GET / Sert l'UI statique (canvas topologie + panneaux Wu-Li / MPR)
GET /api/topology Nœuds (x,y), arêtes, area, seed — sans CDS
GET /api/simulate Topologie + métriques + rôles Wu-Li et MPR + Δ taille CDS
GET /api/broadcast Flood depuis une source : vagues TTL, nœuds atteints, coût unicast DATA

Paramètres communs : n_nodes, radius, seed, target_degree, max_steps. Les builders build_*_response sont testés sans HTTP (test_webapp_api.py).

Lancer la démo
# depuis la racine du repo pip install fastapi uvicorn # voir requirements.txt python3 -m sim.webapp.server # → http://127.0.0.1:8000 # accès distant (ex. Rubik Pi) : ssh -L 8000:localhost:8000 user@rubikpi # puis ouvrir http://localhost:8000 sur le laptop
  • Pas de Bluetooth requis pour la démo CDS / flood
  • Reproductible : même seed → même topologie
  • Résultats indicatifs — pas un substitut au test 3 boards
  • Tests sim : python3 sim/test_sim_validation.py

Intérêt pour le projet
  • Valider les algorithmes CDS (Wu-Li vs MPR) à grande échelle sans flasher des boards
  • Même code que la prod — pas de « simulateur parallèle » qui diverge
  • Démo visuelle pour comparer taille du backbone et coût de flood
  • Le runtime hardware reste sur Wu-Li seul ; la sim permet d'explorer MPR avant branchement prod
  • Complète bb-stack-technique.html (stack) et les tests unitaires tests/
En une phrase (pour la direction)
Le simulateur Web est une coquille géométrique autour du stack BUBBLE-BLUE existant : on remplace uniquement le Bluetooth par un modèle radio 2D, et on expose le tout via une API pour comparer visuellement les stratégies de relais et le coût de diffusion — sans matériel.
